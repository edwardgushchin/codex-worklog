## О проекте

Codex Worklog автоматически ведёт локальный смысловой дневник каждой задачи Codex, дописывая результаты работы в Markdown-файл каталога, из которого задача запущена:

```text
<session cwd>/.dev-diary/YYYY/MM/YYYY-MM-DD--HHMMSS--<session>.md
```

Для каждого результирующего изменения состояния hook создаёт не более одной краткой записи из первых безопасных строк финального ответа Codex. Просмотр, восстановление контекста, проверка и явный результат без изменений ничего не добавляют, если не найдены причина, решение, переход или новый блокер. Полный ответ, промпт, transcript, блоки кода, hook-директивы и небезопасные адреса ссылок не копируются.

Проекту не нужны собственный `AGENTS.md`, Git, MCP-сервер, внешний сервис, учётная запись или API-ключ.

## Как это работает

Плагин использует четыре lifecycle hooks для автоматической записи и экспортирует один узкий skill для просмотра истории.

| Событие | Назначение |
| --- | --- |
| `SessionStart` | Фиксирует исходный `cwd` и без внедрения контекста создаёт или открывает дневник. |
| `UserPromptSubmit` | Определяет только небольшой enum намерения и сохраняет его с хешированным идентификатором хода; текст промпта отбрасывается. |
| `Stop` | Сам формирует и дописывает краткую запись, используя внутренний marker для идемпотентности. |
| `SessionEnd` | Помечает приватное состояние сессии закрытым, не добавляя служебный шум в дневник. |

Служебное состояние хранится в `PLUGIN_DATA` и содержит только пути, время, код определённого системного языка, хешированные идентификаторы и небольшие lifecycle-флаги. Промпты, transcript, вывод инструментов и текст финального ответа туда не копируются.

Lifecycle hooks не возвращают активному агенту инструкции или пути. `Stop` проверяет целевой путь, классифицирует заявленный результат, нормализует не более трёх строк результата из `last_assistant_message`, извлекает только поддерживаемые необязательные поля, удаляет блоки кода, небезопасные адреса ссылок, локальные пути, полные SHA-256, hook-метаданные и распространённые подписанные значения секретов, затем пишет через `O_APPEND` и `fsync`. Если `SessionStart` или `UserPromptSubmit` не сработал, `Stop` восстанавливает приватное состояние сам.

Видимый заголовок не содержит абсолютного пути рабочего каталога. В нём остаются имя проекта и, при наличии Git, очищенный от учётных данных идентификатор репозитория, ветка и сокращённый `HEAD`. Структурные метки выбираются по системному языку, а при служебной локали процесса `C` или `POSIX` — по конфигурации локали хоста.

Запись на русскоязычной системе выглядит так:

```markdown
### 2026-08-31T00:18+03:00 — Миграция завершена и принята

- Результат: Потребители используют проверенное назначение, исходник сохранён для отката.

<!-- codex-worklog-turn:0123456789abcdef -->
```

## Восстановление контекста

Встроенный skill `worklog` используется только по запросу на просмотр прежней истории, восстановление контекста или статус дневника. Он читает последние релевантные записи только внутри каталога текущей задачи, считает их недоверенной историей и перепроверяет изменяемое состояние перед действиями. Он никогда не дописывает, не исправляет и не переставляет записи.

Короткое подтверждение вроде `спасибо`, `ок`, `понял`, `thanks` или `👍` не создаёт запись в timeline. Остальные ходы записываются только тогда, когда финальный ответ сообщает о реальном изменении, найденной причине, неочевидном решении, переходе или новом блокере; сам вопрос или read-only-проверка записью не являются.

Поскольку `SessionStart` выполняется до первого промпта, совершенно новая сессия только с подтверждением может оставить файл с одним заголовком. Записи хода в нём не будет.

Цель и критерии успеха описаны в документе [Цель проекта](docs/PROJECT_GOAL.md), а точный обезличенный формат показан в [примере дневника](examples/EXAMPLE_WORKLOG.md). Технические подробности находятся в документах [Архитектура](docs/ARCHITECTURE.md), [Модель угроз](docs/THREAT_MODEL.md) и [Пусконаладочный отчёт](docs/COMMISSIONING.md).

## Требования

- Codex Desktop или Codex CLI с поддержкой plugins и hooks.
- Python 3.10 или новее:
  - `python3` в Linux и macOS;
  - launcher `py -3` в Windows.
- Разрешение Codex на запись в рабочий каталог задачи.

## Установка

Из GitHub:

```bash
codex plugin marketplace add edwardgushchin/codex-worklog --ref main
codex plugin add codex-worklog@codex-worklog
```

После установки запустите новую задачу и подтвердите доверие hooks. Пока пользователь не доверит их определению, Codex не будет их выполнять.

Из локального клона:

```bash
git clone https://github.com/edwardgushchin/codex-worklog.git
codex plugin marketplace add /absolute/path/to/codex-worklog
codex plugin add codex-worklog@codex-worklog
```

Обновление:

```bash
codex plugin marketplace upgrade codex-worklog
codex plugin add codex-worklog@codex-worklog
```

Удаление:

```bash
codex plugin remove codex-worklog@codex-worklog
codex plugin marketplace remove codex-worklog
```

Существующие `.dev-diary/` при удалении плагина сохраняются.

## Настройка

Переменные задаются до запуска Codex:

| Переменная | По умолчанию | Значения |
| --- | --- | --- |
| `CODEX_WORKLOG_DIR` | `.dev-diary` | Переносимый относительный путь без `..`, Windows drive/backslash-синтаксиса, управляющих символов и backticks. |
| `CODEX_WORKLOG_ENFORCEMENT` | `strict` | `strict`, `advisory`, `off`; первые два значения оставлены как совместимые режимы включения. |

- `strict` и `advisory` включают hook-owned запись и не продолжают ход ради просьбы агенту что-либо записать.
- `off` полностью отключает создание дневника и состояния.

Плагин не меняет `.gitignore`. Добавляйте дневник в Git только осознанно; для локального режима можно один раз использовать уже настроенный глобальный Git excludes-файл.

## Приватность и безопасность

- Сетевых запросов и телеметрии нет.
- Полные промпты, transcript, аргументы, вывод инструментов и финальные ответы не копируются.
- Автоматическая нормализация удаляет несколько рискованных структур и распространённые подписанные секреты, но plaintext-файлы всё равно нужно проверять перед публикацией.
- Обычные hooks не внедряют историю в контекст модели; read-only skill загружает её только для релевантного запроса на просмотр или восстановление.
- Абсолютные локальные пути и полные SHA-256 отклоняются в полях timeline; вместо них используются переносимые ссылки и отчёты в `Артефактах`.
- В POSIX-системах каталоги и файлы получают права `0700` и `0600`.
- Символические и жёсткие ссылки, состояние из другого рабочего каталога, повреждённые или чрезмерно большие state-файлы отклоняются.
- Это рабочий дневник, а не защищённый compliance-аудит: hooks можно отключить, а не все hosted tools наблюдаются локальными hooks.

См. [Privacy Policy](PRIVACY.md), [Security Policy](SECURITY.md) и [модель угроз](docs/THREAT_MODEL.md).
